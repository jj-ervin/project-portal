# ProPro-001 validation plan

Status: planned research. No interviews or competitor feature verification claimed here.

## Decision to resolve
Build a standalone ProPro core, adopt/extend an existing platform, or combine a lightweight universal model with external integrations?

## Comparator set
GitHub Projects, Plane, Backstage, OpenProject; add specialized freelancer, construction and research systems in the evidence matrix. Record official documentation, date accessed, feature availability by tier, API/export support, self-hosting, licensing and observed limitations. Do not infer absence from marketing pages.

## Task-based evaluation
- **Solo freelancer**: Create client project, scope, deliverable, review/approval and payment-status reference without accounting lock-in.
- **Construction**: Plan a porch with measurements, material research, purchasing estimates, dependencies and inspection references.
- **Research**: Track question, protocol, sources, evidence, findings and publication output.
- **Developer portfolio**: Map independent projects to multiple repositories and detect cross-project impact without conflating them.

## Measurements
Time to first project; steps to create a mixed-capability project; task completion; error rate; participant comprehension of hierarchy; data export completeness; mobile usability; accessibility defects; source traceability; setup friction. Capture baseline competitor workflows where permitted.

## Product hypotheses to falsify
1. Mixed-capability project templates are more usable than rigid project categories.
2. Cross-project relationships are useful enough to justify extra data-entry cost.
3. Freelancers value a simple client-facing review flow more than advanced task configuration.
4. A universal model can support construction and research without becoming generic to the point of uselessness.

## Visual acceptance from day one
- Primary navigation and project identity remain understandable on mobile and desktop.
- Every visible action has a real outcome or is clearly disabled.
- Clear separation of project, portfolio, workspace, client and repository.
- Keyboard navigation, visible focus, semantic labels, sufficient contrast and responsive layouts.
- Test real workflows with screenshots and recorded usability findings before accepting UI milestones.

## Deliverable gates
Competitor matrix with evidence; documented user scenarios; model review; integration ownership map; build-vs-adopt ADR; interactive or clickable prototype; explicit MVP exclusions and acceptance tests. Research outputs must identify facts, hypotheses, and decisions separately.
